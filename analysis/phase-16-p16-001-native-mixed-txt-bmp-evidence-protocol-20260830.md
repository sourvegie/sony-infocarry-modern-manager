## What is already established

The reviewed Phase 13–15 records establish these offline or constrained facts:

- strict UTF-8-to-CP932/CRLF TXT authoring and source/payload hashing;
- offline acceptance of a Windows `BM` file with a 40-byte
  `BITMAPINFOHEADER`, 237x320 dimensions, one-bit `BI_RGB`, two-entry
  palette, either BMP row orientation, 32-byte rows, and pixel bounds that
  exactly cover the source;
- deterministic typed TXT/BMP ordering and non-overwriting offline export;
- native four-TXT folder insertion geometry, a leading `..` marker, 0x40-byte
  records, four-byte content alignment, 32-byte TXT wrappers, capacity
  observation, fixed-state observation, and independent post-backup equality
  for the exact P15 four-TXT shape;
- P15-003 physical modern acceptance only for the exact four-TXT `_02` shape.

These facts do not prove that the legacy Manager accepts a newly constructed
TXT/BMP/TXT package, how it stores or wraps the BMP, or that a mixed package
uses the same child-table and content rules. The native capture must answer
those questions directly.

## Facts that still require native evidence

The capture is sufficient only if it makes the following distinguishable:

1. Manager selection and result for exactly one new flat folder with exactly
   the three requested children in order.
2. Complete pre/post path delta, record count, folder record, leading parent
   marker, direct-parent relation, child table, sibling order, record offsets,
   metadata fields, and payload offsets.
3. Exact TXT payload equality and exact BMP payload equality, or an explicitly
   measured native transformation. Any transformation must be reported as an
   observation, not normalized away.
4. The BMP record prefix/wrapper, metadata, dimensions/orientation as stored,
   allocation/padding/alignment, and the relation between metadata and content.
5. Timestamp behavior, fixed-state objects, total-limit capacity behavior,
   and whether existing records or unrelated objects are rewritten.
6. The native `0x101b` declaration, range lengths, `N/M` staging fields,
   completion/result evidence, and byte equality or difference against the
   complete post-operation dynamic model.
7. Manager outcome and post-backup persistence, including any disagreement
   between Manager wording, USB evidence, and backup state.

No unexplained byte difference may be hidden by normalization. Each conclusion
in the later synthesis must be labelled **verified**, **observed**,
**inferred**, or **unresolved**. If the result does not distinguish a required
fact, the outcome is `BLOCKED_BY_EXTERNAL_EVIDENCE`. If native behavior
contradicts the established architecture or safety boundary, the outcome is
`ESCALATION_REQUIRED`. No modern dossier may be prepared from an incomplete
or contradictory capture.
