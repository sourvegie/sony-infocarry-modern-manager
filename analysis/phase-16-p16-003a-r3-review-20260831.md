## Review correction loop

The first independent review found that the opt-in parser read but did not
reject nonzero reserved-tail bytes in `0x001b`. The implementation added the
fail-closed check. The initial regression test was then found to use a dangling
reference and was corrected to use a valid resolved `0x80` reference with only
the reserved tail changed. The final re-review confirmed that the test
isolates the intended rule and found no further material R3 issues.

## Classification and disposition

### Verified

The opt-in fixed-state policy is narrow and fail-closed. It validates and
binds parseable, resolved, aligned, unique, tail-clean display-history
references; rejects active Mark/Bookmark state; permits only the proven
read-state flag transition; and requires references to remain unshifted. The
actual fresh P16-003 geometry conflict is rejected before candidate sealing or
authorization.

### Observed

The owner-confirmed read-state transition and corresponding raw `0x001b`
references are consistent with the established Phase 7 display-history
evidence. The preserved fresh backup remains authoritative offline evidence.

### Inferred

An eventual safe implementation for this exact state needs an explicitly
reviewed offset-preserving geometry or another supported state; this review
does not select one.

### Unresolved

The safe geometry/state decision needed to preserve the exact raw display
history through the additive candidate remains unresolved. Native numeric
completion and operation-specific capacity semantics remain unrelated,
previously documented observations.

## Final disposition

**PASS for the implemented offline correction, with task outcome
`ESCALATION_REQUIRED` for the actual preserved fresh state.** The correction
is not `READY_FOR_HARDWARE_TEST` because the raw `0x001b` references would
shift. Do not rebase the raw block, normalize the fresh backup, access
hardware, or perform a modern transaction until a Project Lead resolves the
geometry/state conflict and a new R3 review passes.
