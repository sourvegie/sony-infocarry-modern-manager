## Scope reviewed

The review covered the prepared typed-package manifest/export/import path, the
optional Library catalog package record, source/package revalidation, queue
grouping and conflict semantics, the ttk directory-picker support, tests, and
the updated status/risk/roadmap/analysis claims. The review also checked that
the change does not import or expose candidate construction, authorization,
transaction, sender, or USB behavior through the new package path.

## Findings and corrections

1. The first implementation read the generic `source.bytes` manifest member
   for every kind. Existing TXT manifests correctly use `source.utf8_bytes`.
   Focused import tests exposed this mismatch; the loader now selects the
   kind-specific authoritative source-size field and checks the resulting
   bytes/hash.
2. The first review pass found that a contained but nested archive path could
   be accepted even though the exporter defines a flat package layout. The
   loader now requires each source path to be the deterministic
   `source/<order>_<original-basename>` location and each prepared path to be
   `prepared/<folder>/<child>`, in addition to resolving symlinks beneath the
   package root.

Both corrections were made before the final validation pass. No raw evidence,
existing reference material, or external package directory was modified.

The approved `TXT and/or BMP` wording was also checked against the public
builder boundary. The historical mixed builder remains both-kinds-by-default,
while the explicitly named content-builder mode accepts only TXT-only or
BMP-only multi-child packages; neither mode creates a device operation.

## Final review assertions

- The package manifest is versioned, canonical-hash-bound, and authoritative
  for contiguous order, flat target paths, child kind/name, sizes, and hashes;
  the explicitly named content-builder mode accepts TXT-only or BMP-only
  packages, while the historical mixed builder retains its both-kinds default.
- TXT children require strict UTF-8 input, CP932 authoring, CRLF policy, and
  exact prepared payload bytes. BMP children require the established 237x320,
  uncompressed 1-bit Windows profile and exact prepared bytes.
- Missing, changed, malformed, unsupported, duplicate, reordered, escaping,
  symlinked, or archive-layout-inconsistent children fail closed.
- The Library stores one package as one non-owning logical item. Existing
  source-file records retain their legacy serialization and meaning; package
  fields are additive. Re-import is idempotent for the exact record, changes
  remain stale under the original identity, and removal is catalog-only.
- Queue selection never infers grouping from several rows. An explicitly
  imported package is one queue entry with ordered child details, destination,
  conflicts, sizes, and lower-bound capacity. Its execution eligibility is
  false, and the plan constructs no candidate, authorization, transaction, or
  sender operation.
- The ttk package action is a directory picker only. Existing one-TXT
  Library/Prepare behavior and read-only Device Manager behavior remain in
  place; normal GUI/CLI transfer is unchanged and disabled.
- The dedicated and regression tests cover deterministic serialization,
  backcompat, containment, order, source/manifest drift, hashes,
  duplicate/conflict handling, catalog non-destruction, grouped queue review,
  and offline UI/report behavior.
