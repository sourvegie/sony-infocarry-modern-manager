# Milestone I.10 — representative small ebook plan

Date: 2026-08-23
Status: **Flat manifest-driven offline plan complete; nested package support blocked.**

`infocarry.prepared_ebook_plan` defines the smallest representative plan that
can be assembled from the current proven logical models: one root-level folder
and a short ordered TXT/BMP sequence. The synthetic test shape is TXT → BMP →
TXT. The plan records the source-manifest hash, prepared-package hash, every
target path, item order and kind, source and payload hashes, wrapper/geometry
metadata, lower-bound growth, capacity fields, timestamp/fixed-state policy,
and expected path delta.

The plan is deliberately not a device candidate. It reports capacity as not
evaluated without a verified fresh backup and native total-limit response;
timestamps and fixed state as unresolved for generalized packages; and
candidate/transaction hashes as absent because no native candidate is built.
The expected read-back is descriptive only: the root folder and ordered child
paths would be added, no path would be removed, and shared content would be
expected to remain unchanged if a future proven operation existed.

Nonempty section lists or per-item section names are rejected rather than
flattened. The smallest evidence needed to support nested ebook sections is an
isolated native folder/package capture with complete before/transaction/after
evidence that proves section directory records, child relationships, order,
timestamps, fixed-state behavior, capacity, and completion. No such operation
is executed or requested by this slice. No ebook or owner-provided copyrighted
source content is tracked.
